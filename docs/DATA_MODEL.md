# Canonical data model

The PostgreSQL migrations are the physical schema contract. Source records remain source-scoped; a UUID is an internal reference, not proof that records from two portals describe the same case, court, person, or event. The model separates mutable current projections from retained observations and acquired evidence.

## Geographic and source-court projections

Migration `0008_canonical_geography.sql` adds populated projections, not an authoritative national court directory:

| Relation / reference | Identity and meaning |
| --- | --- |
| `states` | UUID `id`; unique `label` derived from an observed `sources.state` by trimming surrounding PostgreSQL whitespace only. This is a source-asserted label, not a validated US postal code or legal jurisdiction designation. |
| `sources.state_id` | Nullable UUID FK to `states`; original `sources.state`, `name`, metadata, capabilities, and operational controls remain unchanged. Blank state is unknown/null. |
| `jurisdictions` | UUID `id`; unique `(source_id, source_key)`, where the key is the trimmed source state label (empty for unknown). Represents that portal's asserted geographic scope, not a newly inferred county/district/tribunal. `state_id` references the matching state label; `name` preserves the source name at first projection. |
| `courts` | UUID `id`; unique `(source_id, jurisdiction_id, source_key)`, where the key is the trimmed `cases.court` label. `name` retains the first original label, including its original spacing. |
| `cases.jurisdiction_id` | Required UUID projection of the case's current source scope. Composite FK `(jurisdiction_id, source_id)` prevents referencing another portal's jurisdiction. |
| `cases.court_id` | Nullable UUID current court projection. Composite FK `(court_id, jurisdiction_id, source_id)` prevents a court from another source or jurisdiction. Original `cases.court` remains intact. |

Every geographic projection records JSONB `provenance`: input field, source identity, original input value, matching rule, and projection `version: 1`; court provenance also records the first `sourceCaseId`. These are first-projection provenance records, not a substitute for every observation's lineage. `created_at` is projection creation time, not an inferred historical court establishment date. State labels may be shared between sources, but jurisdiction and court identities never are. Synthetic labels such as `TEST` and `ZZ` remain valid observed labels; they do not assert that those labels are real US states. Unrecognized spellings are retained, not silently mapped to a familiar state.

### Population, changes, and limits

- Database triggers follow the existing canonical identifier/participant-role projection convention. Source writes populate state and source jurisdiction; case inserts and updates of `source_id` or `court` populate current UUID references. Discovery, reconciliation, legacy imports, and metadata feed imports use these same existing writes, not a second geographic ingestion service.
- The migration runner applies DDL, existing-source/case backfill, constraints, and checksum ledger in one transaction. Backfill invokes those same triggers. Previously applied migrations remain immutable. This migration takes transactional schema/write locks; schedule it for a maintenance window for a large populated installation. It is forward-only; a downgrade requires a new forward migration preserving lineage.
- An empty or whitespace-only court remains `court_id = NULL`; no court is inferred from case numbers, source names, state, county, or jurisdiction. Existing upstream `cases.court` values are projected as recorded; the migration does not retroactively decide whether an old source label was a county or a tribunal.
- Matching trims surrounding whitespace only. Case, punctuation, abbreviations, and internal whitespace are significant. No aliases, fuzzy matching, court hierarchy, county crosswalk, geocoding, authoritative registry, or cross-portal legal equivalence is asserted. Even two identically named courts in the same state remain distinct if their source portals differ. Within one source scope, identical labels share a projection; indistinguishable same-name tribunals cannot be separated without a future source-supplied court identifier and explicit migration.
- A court transfer updates the case's current court UUID, retaining the old court row and the original `docket_snapshots.raw` observations. A case source change recomputes both UUIDs even if the label is unchanged. A source state correction creates/reuses the corrected source jurisdiction and reprojects its current cases; earlier geographic rows remain retained. Source display-name changes are not new jurisdiction identities.
- Snapshots are not rewritten or assigned speculative historical geographic FKs. Historical court/source labels remain inside the original observation JSON. A current projection is not evidence that every prior snapshot had that court, state, or source scope. Earlier labels found only in pre-migration snapshots are not backfilled into new court rows.
- Geography does not enable a source, enqueue jobs, change acquisition status, advance refresh dates, or manufacture complete observations. Metadata-only imports remain metadata-only.

## Logical families and physical storage

| Logical family | Actual tables / JSONB and population semantics |
| --- | --- |
| Sources and capability/operational metadata | `sources`, including JSONB `metadata` and `capabilities`, enable/pause/health/concurrency/rate controls; geographic projections above. |
| Cases and identifiers | `cases` is the current source record; unique `(source_id, source_case_id)`. `case_identifiers` stores source IDs, displayed case numbers, and feed identifiers with provenance. Displayed case number alone never merges cases. |
| Case status and classification | Current source status is `cases.status`; transitions are `case_status_history`. County/category/filing-date values are source-derived `cases.metadata` fields when available, with source-specific originals in `metadata.raw` and snapshots. Feed classification remains in import row JSONB and metadata. There is no universal case-type taxonomy or separate normalized classification/history table. |
| Immutable docket observations | `docket_snapshots`: source observation time, completeness, SHA-256 of canonical observation JSON, and full `raw` JSONB. Reconciliation retains snapshots rather than replacing them; duplicates do not create new versions. Application immutability is not a SQL prohibition on privileged updates/deletes. |
| Docket events / filings | `docket_entries` is current source-scoped event identity/order/state with raw source fields. `entry_versions` retains changed event content linked to snapshots; `entry_changes` records additions, modifications, order changes, removals, and other reconciliation changes. `filings` is a populated view of docket entries, not another write path. |
| Document references and attachments | `documents` stores case-scoped source document IDs, JSONB `reference`, current availability/acquisition state, `current_version_id`, and `current_observed_at`. `document_attachments` is a view of documents with an associated filing; standalone documents remain in `documents`. |
| Acquired bytes and versions | `artifacts` indexes content-addressed SHA-256 bytes, size, media type, and storage key. `document_versions` links documents to acquired artifacts, filename, URL, and acquisition time, unique by `(document_id, artifact_id)`. `artifact_acquisition_attempts` records observations/outcomes even when bytes deduplicate. Current pointer/observation time and first acquisition time are different concepts. |
| Participants and roles | `participants` holds case-local source keys, kind/name/current role, and raw JSONB. `participant_roles` is trigger-populated from the current role. No cross-case person, attorney, judge, or organization identity resolution is claimed. |
| Hearings, judgments, charges, representations, organizations, and other source sections | `proceedings` holds source section kind/key and JSONB `data`; `cases.metadata.sections` and `docket_snapshots.raw.sections` retain source structures. Reconciliation populates actual sections supplied by an adapter, with complete/partial semantics. These are not separate nationally normalized hearing, judgment, charge, sentence, attorney, or financial tables. A source that omits a section does not thereby prove no such proceeding exists. |
| Extraction runs and classification | `extraction_runs` links processing to a document version, pipeline/model/prompt/schema versions, status, JSONB result/error, timestamps, and deduplication `run_key`. Document classification is an extraction result, not an independently verified case classification. |
| OCR/text/pages/chunks | `pages` holds page-numbered extracted text, method, and JSONB quality; `chunks` records page and character offsets with full-text indexes. FK links anchor chunks to their extraction run/page. |
| Entities, citations, assertions | `entity_mentions` stores typed mentions with confidence, page/offset provenance, and JSONB data; `citations` is a view of supported citation mention kinds. `assertions` stores extracted text, evidence JSONB, confidence, and data linked to extraction runs. These are derived outputs, not adjudicated facts or independently verified legal authorities. |
| Relationships | `relationships` provides case-scoped source/target/evidence JSONB storage. The existing ingestion/processing pipeline does not automatically populate a resolved relationship graph; the table's presence is not relationship-resolution support. |
| Discovery and coverage | `discovery_partitions` holds source/query hashes, parent subdivision, status/counts/denominator/limitations; `coverage_observations` stores dimension/scope, job lineage, timestamps and limitations. A null denominator means unknown, not complete national coverage. |
| Metadata feed lineage | `feed_imports` records file hash/format/mapping version/checkpoints; `feed_import_rows` preserves raw bytes/text, parsed/normalized JSONB, row hash, original row/line, case link or rejection. `feed_import_refreshes` is the explicit acquisition-intent outbox, not automatic intent for every imported row. |
| Work scheduling and attempts | `jobs`, `job_attempts`, `job_dependencies`, and `job_links` store durable work, retry/lease fencing, outcomes, and dependency lineage. Source acquisition controls remain distinct from local processing. |
| Availability, audit, and access budgets | `availability_history` records availability transitions; `audit_events` records actor/action/resource/details; `request_budgets` enforces principal/window request accounting. These do not replace source observation evidence. |
| Adaptive refresh | Migration0009: singleton `refresh_policy` JSONB with validated intervals/windows; `cases.watched`, `refresh_class`, `refresh_interval_minutes`, nullable due time. Metadata-only observation does not create acquisition intent. |
| Optional case interpretation | Migration0010: `case_interpretation_runs`, `case_interpretation_inputs`, `case_interpretation_assertions`, `case_interpretation_evidence`. Exact current document-version/extraction inputs and page/UTF-16 spans; stale/restricted input sets suppress read results. Derived relationships are assertions, not automatically populated canonical relationship facts. |
| Explicit local retention | Migration0011: default-off `retention_policy`, scheduled `retention_requests`, durable `retention_artifact_deletions`, auditable `retention_events`; sticky case/document withdrawal/purge timestamps and redacted/fenced job references. Original download directories are never targets. |
| Discovery recovery generations | Migration0012: partition generation/recovery counters, last/settled job and attempt, error/failure timestamps. Permanent/exhausted failures stop until explicit replan; bounded transient recovery retains unknown coverage. |
| Artifact revalidation | Migration0013: source `artifact_revalidation_hours` default168/bounded1–720; document reference fingerprint, last verification and next deadline. Current verified bytes skip routine network fetch only within that window and absent revision/reference changes. |
| Schema versions | `schema_migrations` records immutable filename/checksum/application time. Geography provenance version, import mapping version, adapter raw format, and extraction schema/pipeline versions describe different transformations and are not interchangeable. |

## Identity and evidence rules

Complete observations may replace current participant/section projections and mark missing docket content removed; partial observations add knowledge without treating absence as disappearance. Historical snapshots and document bytes remain evidence even when current projections change. Availability, acquisition success, extraction quality, completeness, and source coverage are independent dimensions.

The database is multi-source-ready, not proof of national source coverage. Adapter capabilities, observed restrictions, synthetic fixture provenance, missing source fields, unknown denominators, and unsupported normalized domains must remain visible. No normalized table or UUID alone supplies missing evidence, legal equivalence, acquisition permission, or a claim of exhaustive records.

Focused real-PostgreSQL acceptance is in `test/platform-geography.test.ts`: populated pre-migration upgrade, source separation, blank labels, transfer history, scope changes and FK enforcement, concurrent deduplication, actual metadata feed ingestion, and explicitly synthetic source labels. It requires a disposable `COURT_TEST_DATABASE_URL` and performs no live court/cloud calls.
